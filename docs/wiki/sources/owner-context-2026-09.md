# Owner context — September 2026

This source page preserves durable project direction extracted from recent owner conversations. It intentionally excludes unrelated personal information.

## Core vision

DEKOPEN is intended to become the definitive AI-native operating system for window/door companies, unifying:

- easy visual design;
- deterministic exact engineering;
- BOM;
- profiles;
- glass;
- hardware/accessories;
- cost/pricing;
- quotation;
- cutting optimization;
- production;
- purchasing/inventory;
- CNC/manufacturing;
- documents;
- AI that performs real work.

## Owner quality expectations

- production-grade, not prototype theater;
- superior to sector competitors where the capability matters;
- no silent fallback;
- no invented technical values;
- no fake-green tests;
- no demo authority silently promoted to production authority;
- real browser/product usage during validation;
- agents should investigate and fix missing problems beyond the literal checklist.

## UX concern

A recurring criticism is that software can be technically broad while still feeling “made for robots”.

DEKOPEN should reduce manual translation and internal vocabulary, keep the work object central, and make every control have a real reason.

## Recent visible/domain concerns

Repeated emphasis has included:

- sliding opening semantics;
- separation of sliding vs hinged families;
- opening symbol clarity;
- professional renderer/3D/handle behavior;
- bow/bay composition;
- catalog as evidence-backed technical knowledge;
- quotations/pricing that users can understand and trust;
- factory/cutting/inventory depth;
- CNC as a real machining domain;
- AI as an inspectable operating layer;
- whole-product professional QA.

## Continuity rule

When historical context conflicts with a more recent explicit owner decision, use the newer decision and mark the older one superseded rather than blending both.
