# DEKOPEN product vision

## One sentence

DEKOPEN is a modern, AI-native engineering and operations system in which a window/door product is designed once and becomes the trustworthy source for commercial, manufacturing and machine workflows.

## The product center

The core object is not a quote, ERP row or chat thread.

It is the configured fenestration product, with stable geometry and explicit technical authority.

That product should drive:

- visual authoring;
- validation;
- BOM;
- cost and price;
- quotation visuals;
- customer approval;
- material requirements;
- profile/glass/hardware schedules;
- cutting;
- production;
- machining/CNC;
- traceability.

## What DEKOPEN must combine

Legacy sector software often has domain depth but dated interaction patterns. Modern SaaS often has polished UI but lacks fenestration truth.

DEKOPEN's opportunity is the combination:

**fenestration depth + deterministic engineering + modern direct manipulation + end-to-end operations + AI-native work.**

## Trust contract

A user must be able to answer:

- What is this product?
- Is it physically/configurationally valid?
- What is unknown?
- Why is it blocked?
- Why does it cost this amount?
- What material is required?
- What will the factory do?
- What will the machine do?
- What changed between revisions?

The system should never force the user to trust unexplained magic.

## Completion standard

A feature is not complete because:

- a page exists;
- a button exists;
- a mock renders;
- a unit test passes;
- an AI response sounds confident.

A feature is complete when its domain logic, authority, UX, workflow continuity, downstream integration, error behavior, permissions, auditability and real-product testing agree.
